Two ways to adopt DocBen

Choose the path that fits how your team works.

Both paths run the same validation engine against the same PhilHealth rules. The difference is how claims get in: typed into a browser, or sent by your own software.

Path A · Web app

DocBen web app

Enter and validate claims right in your browser — no development needed.

  • Fill in the CF4 form section by section
  • Attach supporting documents (images or PDF)
  • Click Validate Claim and see every issue on screen
  • Fix, re-validate, then save drafts and track your claims

Best for: billing and records staff, clinics, and hospitals that want to start validating claims today.

Web app guide Open the web app ↗
Path B · API

DocBen API

Validate claims straight from your own system, automatically.

  • REST API with API-key auth and an OpenAPI spec
  • Send DocBen JSON or the official eClaims 3.0 XML
  • Submit, then poll for the score, rejection reasons, and DRG
  • Client examples in JavaScript and TypeScript

Best for: hospitals and software vendors with an existing HIS, EMR, or billing system.

Path A · Web app

From a blank form to a clean claim

The DocBen web app walks your team through the PhilHealth CF4 and flags every problem before the claim goes out — no integration work required.

  1. Sign in. Create an account and enter the registration code from your administrator.
  2. Create a claim. Fill in the six CF4 sections: HCI, patient, reason for admission, course in the ward, drugs, and outcome.
  3. Attach documents. Upload lab results, imaging reports, and other supporting files.
  4. Validate. The AI Analysis panel lists each issue and explains why.
  5. Fix and re-validate until it reads “This is likely valid.”
